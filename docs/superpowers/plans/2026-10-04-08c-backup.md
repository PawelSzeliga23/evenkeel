# Plan 8c — Kopia portfela i opis odświeżania cen — Implementation Plan

> Executed inline on branch `feature/backup`. The owner waived the spec and plan reviews (2026-10-04); ask only
> before merging.

**Goal:** download the whole portfolio of the signed-in user as one JSON file and restore it (replacing everything),
plus a read-only page describing the price refresh schedule.

**Spec:** `docs/superpowers/specs/2026-10-04-08c-backup-design.md`.

**Tech:** FastAPI + SQLAlchemy (generic per-table serialisation from model columns), pytest in Docker
(`docker compose run --rm api pytest -q`); React + TanStack Query + Vitest; Playwright e2e. No migration.

## Global constraints

- One table description (`app/backup/tables.py`) drives both export and restore.
- Restore validates the whole file before touching the database and replaces everything in one transaction.
- Shared rows (instruments, bond series) are only inserted when missing, never changed.
- Polish user-facing messages exactly as in the spec.

### Task 1: Table description and export

**Files:** create `api/app/backup/__init__.py`, `tables.py`, `export.py`, `schemas.py`, `router.py`;
modify `api/app/main.py`; test `api/tests/test_backup_api.py`.

- [ ] `tables.py`: `TableSpec(name, model, refs: dict[column, target_table], owner: how rows of a user are selected)`
  in insert order: accounts, imports, transactions, position_lots, xtb_snapshots, bond_holdings, savings_accounts,
  savings_rates, savings_balances, savings_flows, tags, tag_links, theses, journal_entries, scenarios, ai_reviews,
  corporate_actions (manual). `SHARED = {instruments: key xtb_ticker, bond_series: key series}`.
  `SKIPPED` = tables deliberately not in the backup (users, refresh_tokens, prices, fx_rates, cpi, nbp_ref_rates,
  wrapper_limits, daily_valuations, instruments/bond_series as user tables) — a test checks every table of
  `Base.metadata` is in one of the three.
- [ ] `export.py`: `export_user(db, user) -> dict` — rows per spec (all columns except `user_id`), values made JSON
  safe (Decimal → str, date/datetime → isoformat); instruments and bond series referenced by any exported row,
  including scenario JSON and manual corporate action targets; shared columns without `id`-only volatile fields
  (`price_checked_at`, `price_error`, `created_at`). Envelope with `format`, `version` 1, `exported_at`,
  `app_version` (from `pyproject`/settings, same as the web footer).
- [ ] `GET /api/backup` with `Content-Disposition` attachment.
- [ ] Tests: export of a seeded user contains each table with the expected counts, decimals as strings, no
  `user_id`, no other user's rows; the coverage test of `Base.metadata`.
- [ ] Commit `feat(api): portfolio backup export`.

### Task 2: Check and restore

**Files:** `api/app/backup/restore.py`, router, schemas; tests in `test_backup_api.py`.

- [ ] `read_backup(content: bytes) -> Backup`: JSON parse, envelope checks, per-table column checks against the
  model, required columns (non-nullable without server default, except `id`/`user_id`), reference checks (every
  `refs` value and the JSON id fields point to a row of the file or are null). Errors → `ApiError(422,
  "invalid_backup", message)`.
- [ ] `counts(backup)`.
- [ ] `restore(db, user, backup)`: delete the user's data, insert missing shared rows (instrument without
  `price_checked_at`), insert rows in spec order mapping file ids → new ids (transactions' `transfer_pair_id` set
  in a second pass), remap JSON ids, set `preferences`/`base_currency`, `mark_stale(dt.date.min)`; any
  `SQLAlchemyError`/`ValueError` on the way → rollback and 422.
- [ ] `POST /api/backup/check`, `POST /api/backup/restore` (`confirm` form field must be `ZASTĄP`), 20 MB limit
  like imports, background recompute like account deletion.
- [ ] Tests: round trip A → B equal after id normalisation; B's old data gone, C untouched, stale set; missing
  instrument created with `price_checked_at` NULL; rejections (not JSON, other format, version 2, unknown column,
  dangling reference, missing confirm, too large, a bad value deep in the file keeps old data).
- [ ] Commit `feat(api): restore a portfolio backup, replacing the user's data`.
