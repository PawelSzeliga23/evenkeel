# Plan 7c — Walory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Analiza → Walory: a heat map (treemap) of holdings coloured by the period's gain, a ranking, and gains by account and by kind, for Dzień/Tydzień/Miesiąc/Rok/Od pocz. roku/Wszystko.

**Architecture:**
- **API:** `app/analytics/holdings.py` computes each holding's gain from the cached `daily_valuations` (payout values on the base day and the end day) plus the PLN amounts of transactions (instruments) or the rows' `net_flow_pln` (bonds, savings) in the window. `GET /api/analytics/holdings` serves it.
- **Web:**
  - `charts/treemap.ts` is a squarified layout;
  - `screens/holdings/` holds the screen, the heat map, the ranking and the tables;
  - the card goes on Analiza.

**Tech Stack:** FastAPI, SQLAlchemy, pytest; React, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-02-07c-holdings-design.md`

## Global Constraints

- Periods are the wire values `1d|1w|1m|1y|ytd|all`, with labels Dzień, Tydzień, Miesiąc, Rok, Od pocz. roku, Wszystko.
- Gain = `V(end) − V(base) − net money in + income` (the spec's formula). Gain % has its own base (`V(base)` + purchases) and is `null` when that base is ≤ 0.
- Colour saturation: ±3 / 5 / 10 / 30 / 30 / 50 % for 1d / 1w / 1m / 1y / ytd / all.
- Commands: `docker compose run --rm api pytest -q`; `cd web && npx vitest run && npx tsc --noEmit`; `npx playwright test`.

## Review Focus

1. **A holding bought inside the period:** its purchase is not counted as gain. Pinned in Task 1.
2. **A holding sold out inside the period:** its realized gain appears, even though `V(end)` is 0. Pinned in Task 1.
3. **Tiny holdings:** the treemap keeps every tile with positive area, and the tile still opens its details even without a label. Pinned in Task 2.

### Task 1: API

**Files:**
- Create `api/app/analytics/holdings.py` and `api/tests/test_holdings_api.py`.
- Modify `api/app/analytics/router.py` and `api/app/analytics/schemas.py`.

**Interfaces — Produces:**
- `HoldingsPeriod = Literal["1d","1w","1m","1y","ytd","all"]`;
- `holdings(scope, account_ids, period) -> HoldingsOut`, with the schemas `HoldingAccountOut`, `HoldingOut`, `GroupGainOut` and `HoldingsOut` as in the spec;
- route `GET /api/analytics/holdings`.

**Steps:**
- [ ] Tests with the valuation seed (SXR8.DE: 2 units bought 2026-03-02, 500 EUR → 600 EUR on 09-25, EUR 4.30 → 4.25, dividend 40 − 6 on 06-15, valued to Sat 09-26):
  - `all`:
    - the SXR8 item has `value_pln` = the seed's payout value (5074.50);
    - gain = 5074.50 − 0 − 4304.30 + 34.00 = 804.20 (matching the summary's gain);
    - `gain_pct` = 804.20 / 4304.30.
  - `1d`:
    - base = Thu 09-24, end = Sat 09-26, with no transactions;
    - gain = V(09-26) − V(09-24) = 5074.50 − (2 × 500 × 4.30 × 0.995 → see the seed) = the summary's `day_change_pln` for that position.
    - Assert against `/api/positions` `day_change_pln` for SXR8, or compute the two V from `daily_valuations` in the test.
  - **Purchase in the period:** a second buy on 09-25 of 1 unit at 600 EUR (amount −2550). `1w` gain excludes it: gain = ΔV − 2550.
  - **Sale in the period:** sell both units on 09-25 for 5100. The item stays with value 0 and gain = 0 − V(base) + 5100.
  - **Bonds:** EDO via `BondHolding` + `BondSeries` in the seed, valued; the bond item's gain = V(end) − cost for `all`.
  - **Savings:** a savings account with a deposit; gain = interest.
  - **Two accounts with the same instrument:** one item with two `accounts`.
  - **Account filter:** only the chosen account's items; a foreign account is 404.
  - **No valuation:** `period` null, empty lists.
  - `by_kind` keys and names; `by_account` sums.
- [ ] Implement:
  - read the cached rows for the base and end days (grouped per component key);
  - flows of bond and savings rows in the window;
  - transactions in the window, with `amount_pln` from `app.portfolio.service`;
  - assemble the items, sorted by gain descending.
- [ ] PASS + full suite. Commit `feat(api): holdings gains for a period — heat map and ranking data, by account and by kind`.
