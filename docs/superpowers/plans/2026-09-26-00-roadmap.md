**Diagnoza zawyżonej wyceny (2026-09-29, do planu 6d):** portfel właściciela: aplikacja ≈ 1 723 zł, XTB ≈ 1 710 zł. Koszt zakupu i ilości zgodne z XTB; różnica w wartości bieżącej każdej pozycji w walucie obcej: SXR8 +0,82 %, EIMI +0,66 %, VIE +0,48 %. Przyczyny: 0,5 % przewalutowania XTB przy sprzedaży (silnik liczy po kursie średnim NBP) + bid vs cena zamknięcia i różnica czasu (reszta, najwyraźniej na SXR8). TER nie jest przyczyną — jest już w cenie ETF-u.

Po planie 6d (2026-09-30), wycena do wypłaty vs eksport XTB z 26.09: SXR8 −0,21 % (wcześniej +0,29 %), EIMI +0,37 % (+0,88 %), VIE +0,11 % (+0,61 %); reszta to różnica czasu ceny.

**Na później — porządki w bazie:** w bazie właściciela jest 8 kont użytkownika z tymi samymi danymi (16 rachunków, każdy import 8 razy) — konta z testów rejestracji. Do usunięcia zbędnych użytkowników po decyzji właściciela, które konto zostaje (usuwanie kaskadowe przez `users` → `accounts`).

**Na później — podpowiedzi AI po przeglądzie portfela (pomysł właściciela, 2026-09-29):** model językowy (Claude przez API) dostaje zanonimizowany obraz portfela z naszych danych — alokację, koncentrację, ekspozycję walutową, koszty (prowizje, przewalutowanie, TER), wykorzystanie limitów IKE/IKZE, zwrot vs benchmark — i zwraca krótkie obserwacje i pytania do przemyślenia (np. „80 % w jednym ETF-ie”, „niewykorzystany limit IKZE”). Ton jak rozmowa z doświadczonym znajomym: najpierw ogólna ocena, potem konkretne zauważenia i ryzyka, np. „Portfel jest dobrze zdywersyfikowany geograficznie, ale zauważ, że masz sporą ekspozycję na USD (ok. 70 % przez S&P 500)” albo „Rynki wschodzące (EIMI) wiążą się z większą zmiennością i ryzykiem walutowym — przy obecnym udziale 12 % spadek o 30 % obniżyłby portfel o ok. 3,6 %”. Mocne strony i ryzyka, z liczbami z naszej wyceny. Zasady do ustalenia przy projektowaniu: to obserwacje, nie rekomendacje inwestycyjne (wyraźny dopisek); liczby tylko z naszej wyceny, nie wymyślane przez model; zgoda użytkownika na wysłanie danych; bez danych osobowych (numerów rachunków). Najsensowniej po etapie 2 (analityka), bo korzysta z jej miar.

**Otwarty punkt (odłożony 2026-09-28):** test PWA na iPhonie — ekran początkowy, tryb standalone, service worker przez HTTPS (tymczasowy `cloudflared tunnel --url` albo `mkcert`), safe-area na urządzeniu. Plany 6a/6b budują PWA, ale sprawdzają je tylko w przeglądarce na komputerze.

Kolejność: 1 → 2 → 3 → 4 → 5 → 6 → 7. Plany 3 i 5 mogą iść równolegle po planie 2.
Plan 6 może zacząć się sesją designu wcześniej — nie zależy od backendu, dopóki nie podpina API.

## Decisions carried from Plan 1 review

- Plan 6 (frontend): refresh must be single-flight across tabs (Web Locks API or
  BroadcastChannel) and never run twice on mount (React StrictMode) — the backend treats
  concurrent use of one refresh token as theft and revokes all sessions.
- Plan 6: show Polish messages by mapping error `code` / validation `type`, never display
  pydantic `msg` (English).
- Plan 3 (worker): prune `refresh_tokens` rows that are expired or revoked for more than 30
  days.
- Deployment plan (home server behind Cloudflare Tunnel): rate-limit key must use the real
  client IP (`CF-Connecting-IP` / `uvicorn --proxy-headers` with a trusted proxy), otherwise
  all users share one login budget.
- Any future change to `refresh()`: add an endpoint-level concurrency test (two concurrent
  `/refresh` calls with a barrier); the current test exercises the SQL claim pattern only.
- Later: store `Settings` on `app.state` so `create_app(settings)` is fully applied without
  `dependency_overrides`.

## Spike 2026-09-26: źródła danych rynkowych (dla planu 3)

- **Stooq — odpada.** `stooq.com/q/d/l/?s=…&i=d` zwraca stronę z weryfikacją JavaScript (ochrona przed botami) zamiast CSV — dla każdego symbolu.
- **Yahoo chart API — działa** (`https://query1.finance.yahoo.com/v8/finance/chart/{symbol}?range=…&interval=1d`, nagłówek `User-Agent`): ceny dzienne (`close` i `adjclose`), ok. 1250–1300 sesji na 5 lat, a `meta.currency` podaje walutę notowania → wypełnia `instruments.currency`.
  - Sprawdzone: SXR8.DE (EUR), EIMI.L (USD), VIE.PA (EUR), SPY (USD), PKN.WA (PLN), ^GSPC (USD), EURPLN=X.
  - Mapowanie sufiksów XTB → Yahoo: `.DE`→`.DE`, `.UK`→`.L`, `.FR`→`.PA`, `.PL`→`.WA`, `.US`→bez sufiksu (NL→`.AS`, IT→`.MI`, ES→`.MC` do potwierdzenia przy pierwszym użyciu).
  - **Benchmark WIG/WIG20 niedostępny** (`WIG.WA` = 1 dzień, `^WIG20` = brak) → w planie 7 użyć ETF-u na polski indeks lub innego źródła; S&P 500 = `^GSPC`.
  - To nieoficjalne API: dostawca za interfejsem `PriceProvider`, obsługa błędów/limitów, fallback = ostatnia cena z importu XTB.
- **NBP API — działa** (`api.nbp.pl/api/exchangerates/rates/a/{kod}/{od}/{do}/?format=json`, kurs `mid` z tabeli A) → źródło kursów walut do wyceny w PLN.
- **GUS BDL API — odpowiada** (`bdl.stat.gov.pl/api/v1/…`, HTTP 200) → źródło inflacji do potwierdzenia właściwej zmiennej w planie 5.

## Spike 2026-09-26: zasady obligacji skarbowych (dla planu 5)

Źródło: obligacjeskarbowe.pl (strony ofert) + list emisyjny EDO0936 (załączniki 2 i 3). Oferta wrzesień 2026:
OTS1226 2,00% stałe · ROR0927 4,15% zm. · DOR0928 4,15% zm. · TOS0929 4,40% stałe · COI0930 4,75% (potem inflacja + 1,50%) ·
ROS0932 5,00% · EDO0936 5,35% (potem inflacja + 2,00%) · ROD0938 5,60%. **Parametry różnią się per seria → tabela `bond_series` wypełniana per seria, nie per rodzaj.**

- **Inflacja:** „stopa wzrostu cen towarów i usług konsumpcyjnych, przyjmowana dla 12 miesięcy i ogłaszana przez Prezesa GUS
  w miesiącu poprzedzającym pierwszy miesiąc danego okresu odsetkowego”; inflacja ujemna → 0. Stopa okresu = inflacja + marża.
- **Wartość EDO w dniu „d” (załącznik 3):** `WP_k = N · (1+r1)·…·(1+r_{k-1}) · (1 + r_k · a_k / ACT_k)`,
  `a_k` = rzeczywista liczba dni od pierwszego dnia okresu k (włącznie) do dnia „d” (wyłącznie), `ACT_k` = liczba dni okresu k;
  wynik **na jedną obligację, zaokrąglony do 2 miejsc**; **`WP_k < 100` → `WP_k = 100`** (opłata nie zjada kapitału EDO).
  W dniu wykupu: `W = N · Π(1+r_i)`, zaokrąglone do grosza.
- **Opłata za wcześniejszy wykup (zakupy od 1.09.2024):** EDO 3,00 zł/szt., COI 2,00 zł/szt. (dla starszych zakupów inne stawki → per seria).
  EDO: opłata w pełnej wysokości albo do wysokości narosłych odsetek. **COI: tylko w 1. okresie limit do odsetek; w kolejnych okresach
  opłata w pełnej wysokości** (może obniżyć kwotę poniżej nominału) — potwierdzić w liście emisyjnym COI przed implementacją.
- **Podatek:** od (odsetki − opłata). **Wcześniejszy wykup:** nie wcześniej niż 7 dni od zakupu i nie później niż 20 dni przed wykupem
  (bez ograniczeń przy zwrocie/wypłacie z IKE/IKZE).
- Do sprawdzenia w planie 5: listy emisyjne pozostałych rodzajów (COI, TOS, ROR/DOR, ROS/ROD), stawki opłat dla zakupów sprzed 09.2024.
